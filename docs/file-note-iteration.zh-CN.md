# 一等文件笔记迭代

## 目标

让非 Markdown 文件作为笔记出现在所属笔记本中并可持续管理。原始字节继续保存在对象存储；未知格式始终安全降级为文件信息和下载。

## 本次迭代

- 保持 `memo` 作为笔记身份和生命周期主体。
- 每篇文件笔记允许一个有效主资源（`primary`），并保存稳定 `formatKey`。
- 支持拖入单个文件。Markdown 继续创建文本笔记；其他非图片文件创建文件笔记。
- Memo API 返回最小文档描述。
- 列表能识别文件笔记，打开后进入通用文件页。
- 支持下载及带 SHA-256 冲突保护的文件替换。
- 主文件内容或文件名变化时刷新所属 memo，让现有 memo 同步能够感知变化。
- 禁止脱离 memo 单独删除主资源。
- 备份和恢复保留主资源身份及格式标识。
- 为旧客户端保留系统生成的 Markdown 附件链接；普通 Markdown 编辑接口不得移除文件标记。

## 明确不做

- CLI 二进制工作区同步和文件历史版本；CLI 遇到文件笔记会明确跳过并报告，不把它伪装成 Markdown。
- Office、PDF 或未知文件的正文提取和全文检索。
- D2 预览/编辑及第三方格式注册。
- 把思维导图、表格、海报或信息图迁入新渲染分发。
- 文件笔记模板、合并语义或另一套平行文件目录。

## 验收

1. 拖入非 Markdown 文件后创建一篇 memo 和一个主资源。
2. 列表能识别文件笔记；打开后显示当前文件信息并可下载。
3. 替换文件必须携带当前 SHA-256；过期值返回 `409 resource_conflict`。
4. 主文件替换或重命名会改变所属 memo 时间，并进入现有 memo 同步。
5. 资源库不能单独删除主资源；删除和恢复 memo 时随之处理。
6. 备份恢复后主资源身份和格式标识不丢失。
7. 现有 Markdown 和结构化笔记继续使用原编辑器路由。

## 实施记录

- 数据库：新增迁移 `0098_primary_file_resources.sql`，为资源增加 `role`、`format_key`，并限制每篇 memo 只能有一个有效主资源。
- 协议：Memo API 增加 `document` 描述；资源 API 返回主资源身份和格式。
- Web：文件拖入、列表识别、通用文件页、下载和带 SHA-256 校验的替换已接通。
- 安全边界：主资源必须属于当前 memo；普通编辑接口不能移除文件标记；资源库不能单独删除主资源。
- 兼容：备份、恢复和笔记复制保留主资源元数据；旧附件链接继续保留。
